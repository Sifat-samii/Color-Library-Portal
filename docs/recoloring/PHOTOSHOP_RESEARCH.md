# Photoshop recoloring: primary-source findings

Reviewed 15 October 2026. This note separates Adobe API contracts from local host evidence and remaining qualification work. It supports the Stage 1A development harness; it does not establish production color accuracy.

## Current evidence and support boundary

The checked-in [local report](verification/photoshop-25.3.1.json) records Photoshop **25.3.1**, 25 passing synthetic technical fixtures, zero failures, `technicalGatePassed: true`, and `productionQualified: false`. The fixtures exercise bounded SHA-256 and frozen-source recovery, corruption/cancellation refusal, identity-safe document creation/opening, reviewed source preparation, stale/duplicate-name protection, insertion below finishing layers, hidden-recipe independence, native A/B/C adjustments, opt-in tinted Black & White/Levels, native-depth arbitrary reduced reads, soft and offset 16-bit masks, provisional updates, rollback, profile conversion, layered save/reopen, independent variants, manual-change protection, existing selections/channels/paths, reduced-read bounds, and bounded fitting against Photoshop renders. Reproduce with `npm run test:recolor:photoshop` on a licensed Windows Photoshop installation. The 96 × 64 rendering fixtures and 1024 × 768 sampling fixture do not establish commercial garment quality or large-document performance. The report records the SHA-256 identity of its tested module bundle. Host evidence was refreshed on 16 October (Asia/Dhaka); [post-audit progress](NATIVE_ENGINE_PROGRESS.md) records the changes.

The local Windows runner successfully dispatches a `.psjs` through COM `DoJavaScriptFile` on 25.3.1 and verifies the UXP environment. Treat this as tested local behavior, not a general Adobe COM guarantee. Adobe documents File > Scripts > Browse, drag/drop, and Actions as standalone `.psjs` launch routes, available since Photoshop 23.5. [Adobe UXP scripting](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/uxpscripting)

Use manifest API version 2 and explicit capability/version checks. The Selection DOM requires 25.0; `executeAsModal.timeOut` requires 25.10, so the 25.3.1 harness must not depend on that option. An installed newer runtime is not evidence that older hosts behave identically. [Selection versions](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/selection), [Modal options](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal)

## Selection, layer alpha and masks are different inputs

- `Selection.load(layer)` loads **pixel transparency**, not the layer's mask. Load a saved alpha channel using `Selection.load(channel)`. Preserve the original selection/channel state. [Selection contract](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/selection)
- Read a pixel mask with `imaging.getLayerMask({documentID, layerID, kind: "user"})`; read the active selection with `imaging.getSelection`. Preserve the returned bounds and offsets. The imaging interface distinguishes user/vector mask reads and supports user-mask writes. [Imaging contract](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)
- Convert a named vector path using `PathItem.makeSelection` with explicit feather, antialias and selection-operation arguments. Keep the original path unchanged. Path IDs are documented for use during the document's lifetime. [PathItem contract](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/pathitem)
- Density and feather are separate layer-mask properties. Do not infer effective rendered coverage solely from raw mask pixels. Unsupported nondefault settings or combined masks must produce an explicit restriction or a validated native normalization path. [Layer mask properties](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/layer)

Capture the desired coverage and then deselect before creating adjustment children. An active selection automatically becomes an adjustment mask. Apply the soft material mask once to the outer group; repeated child/group masks can change fractional edge coverage. [Adobe adjustment-mask behavior](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/color-adjustment-fill-layers/use-layer-masks-to-target-adjustment-or-fill-layers.html)

Local 25.3.1 testing found unavailable channel/path IDs on the returned objects. The harness therefore validates a current collection index plus its name in the working duplicate before loading. It does not persist those indices as cross-reopen identities. Reading `layerMaskDensity` and `layerMaskFeather` uses the documented DOM properties; the broad layer ActionJSON descriptor did not reliably include them on this host.

Adobe's object-recoloring tutorial uses a masked group, a Solid Color layer in Color blend mode, and a separate brightness adjustment. This supports native layered recoloring as a mechanism; it does not promise one recipe for every material. Color mode retains underlying brightness, so lightness changes require independent tonal control. [Adobe object-recoloring workflow](https://helpx.adobe.com/ph_fil/photoshop/how-to/change-color-object.html)

## Native rendering, modal scopes and safe updates

Prefer DOM methods where available, using `batchPlay` for native adjustment creation/editing. Adobe documents recording an Action and copying it as JavaScript to obtain accepted descriptors. A resolved `batchPlay` promise can contain error descriptors: inspect every result and throw on failure. [ActionJSON and errors](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/batchplay)

The installed 25.3.1 first-party files `Required/UXP/com.adobe.photoshop.adjustments-panel/adjustments.js` and `presets/presets.json` provide native adjustment examples; `Required/UXP/photoshop.js` contains fill/group builders. The host fixtures, rather than these examples alone, establish the currently exercised A/B/C descriptors. Do not use Photoshop Services' REST adjustment schemas as if they were desktop ActionJSON.

All plugin document mutations require `executeAsModal`. Suspend history for each bounded transaction; commit on success and roll back that transaction on error/cancellation. Modal completion automatically resumes remaining suspensions. Keep modeless UI interaction and numerical search outside persistent modal locks. Ordinary modal execution can silence action notifications to other plugins, so listeners alone cannot prove the source unchanged. [Adobe modal/history contract](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal)

Use a reusable full-resolution working duplicate and evaluate native Photoshop composites. Serialize updates and discard superseded requests. Downsampled reads may use cache pyramid levels, whose returned bounds are relative to that level. A reduced read is useful for coarse fitting, but final mask/edge/detail checks require correctly mapped full-resolution samples. Dispose imaging buffers and avoid unnecessary full-canvas JavaScript allocations. [Adobe imaging bounds and memory guidance](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)

Bind sessions to current document IDs and state; revalidate before Apply. Plugin-owned provisional groups may be updated while their expected state is intact. Designer changes must prevent destructive replacement. Preserve previous committed variants, and create an independent new variant rather than silently rebuilding a designer-edited group. Cancellation must not rewind unrelated source-document history.

Layer IDs are targeting identifiers, not plugin-owned permanent UUIDs. PSD stores layer IDs, but that does not establish immutable identity across replacement, duplication, external rewriting or every save workflow. Re-enumerate and validate after reopen. Use explicit ownership markers/manifests, and treat missing or duplicate identity as ambiguous. [Layer IDs](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/layer), [Adobe PSD format](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)

## Profiles, measurements and deliverables

Inspect source mode, depth and profile before analysis. Preserve the original document; normalize only an owned working duplicate. The current harness chooses 16-bit Adobe RGB as its working convention, not because Adobe guarantees that convention is optimal for every client. Profile conversion and profile assignment are different operations. `Document.convertProfile` exposes conversion intent, black-point compensation and dithering. [Document/profile API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/document)

Specify imaging color space, profile and depth explicitly. Adobe documents Lab data using **Lab D50**, Photoshop's default 16-bit sample range as **0–32768**, and `fullRange` for 0–65535 buffers. Transparency matting and implicit working-profile defaults can invalidate measurements. Compare like-for-like profiles and distinguish RGB encoding from physical reflectance. [Imaging color interpretation](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)

Optimize the actual rendered output against qualified diffuse-material reference regions, with separate protection for texture, highlights, shadows and edges. A fabric pixel in a shadow should not be forced to equal a flat swatch. A low numerical color difference on a synthetic patch is not proof of physical matching, metamerism control, material realism or client approval.

Save layered masters with profile embedding; PSD save options explicitly support both. Produce web renditions from an export duplicate converted to sRGB. Verify files after reopening, rather than trusting file extensions or requested options. WebP is native for 8-bit RGB, but it is absent from the documented UXP `saveAs` methods, requiring a separately validated adapter. PSD has a 2 GB limit; preserve a PSB path for large masters. [Layered save options](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/objects/saveoptions/photoshopsaveoptions), [WebP constraints](https://helpx.adobe.com/photoshop/desktop/save-and-export/save-files/save-and-open-webp-files-in-photoshop.html), [File-size limits](https://helpx.adobe.com/photoshop/kb/optimize-photoshop-cc-performance.html)

## Unresolved qualification before production

1. Representative, client-authorized photographs and senior-retoucher reference PSDs: matte, satin, heather, mesh, complex seams, labels, mixed materials and extreme light/dark transitions. Establish review procedures and material-specific acceptance thresholds from that dataset.
2. Independent color-conversion checks against Photoshop's profile-managed Lab measurements, including neutral colors, saturated colors and near-gamut boundaries. Measure reference-region agreement without scoring legitimate illumination variation as error.
3. Real-resolution masks and edge inspection: fractional coverage, feather/density, vector/pixel combinations, antialiasing, halos, original-color contamination and protected background/hardware.
4. Actual workstation latency/memory tests, cancellation during slow operations, long preview sessions, rapid slider input, modal collisions and recovery after failure. Small synthetic fixtures do not establish interactive performance.
5. Broader host/OS, locale, PSD/PSB save/reopen/Save As and cross-workstation tests. Test independently from the locally successful COM launcher using Adobe's documented launch path.
6. Cross-view consistency, calibrated human color review and export round trips. Do not claim universal physical accuracy from an unprofiled image or an unmeasured swatch.

SAM segmentation and shared-GPU processing remain separate later-stage work. Native masks plus human review remain necessary until those components are independently evaluated. Generative fill/harmonization must not be assumed to preserve exact material detail or color: Adobe describes Harmonize as changing lighting, colors, shadows **and details**. [Adobe generative feature definitions](https://helpx.adobe.com/photoshop/desktop/generative-ai/generative-ai-features-overview.html)
