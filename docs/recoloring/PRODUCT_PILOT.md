# Integrated Color Library recoloring pilot

**28 October upgrade:** [Pilot 0.7.0 professional fabric engine](PROFESSIONAL_FABRIC_ENGINE.md) supersedes the selection/scoring behavior below for new previews. It restores all four methods, introduces Recipe/QualityReport v2, linear-light multiscale analysis, regional clipping, local corrections, constrained search, explicit draft overrides, feedback records and verified masters. Historical version sections remain evidence of their respective builds. Formal visual qualification is deferred.

19 October 2026 (Asia/Dhaka). The owner chose a product-first sequence: build a usable designer workflow, evaluate real results, then improve it. Reviewing every historical PSD is not a prerequisite for using this pilot. Ambiguous historical benchmark sources remain excluded from scored claims.

## What this build contains

The existing **Pixofix Color Library** panel gains a **Recolor / Pilot** toolbar and an **Apply Color** action beside **Open Reference** on each approved reference. Search, client selection, favorites, previews, sync, approvals and ordinary reference opening retain their existing transport and data contracts. There is no remote Photoshop command bridge, pixel-upload service, new database requirement, HEX requirement, segmentation worker or GPU dependency.

The pilot uses the current appearance of the explicitly selected product document. It creates a layered frozen Adobe RGB (1998), 16-bit working duplicate. Designers prepare any historical recoloring visibility themselves before capture; the pilot does not infer unknown layer purpose. Opened library references are recorded so that they cannot silently become a subsequent product source.

Adobe RGB catalog HEX chips are converted to sRGB display values in the pilot; the original stored codes and approved images are unchanged. This corrects chip interpretation without treating a HEX chip as the recoloring target.

Material coverage comes from an explicit Photoshop selection, layer mask, alpha channel or path. Source binding persists when references become active. The product workflow compares adjustment-only methods B/C/D through Photoshop-rendered fitting, without adding a Solid Color fill. The panel offers preview, before/after, tone/intensity controls, native editable Apply Color, independent variants, per-target session settings and layered PSD/PSB saving.

Every new variant starts from the frozen source. A manually changed provisional preview is retained when a new variant is created. Ending a session leaves previews and committed results open. Native edits are not automatically merged into another target. Committed results remain editable through ordinary Photoshop tools.

## First recoloring

1. Open the intended original product image in Photoshop. Prepare any existing adjustment visibility as desired. Keep the tagged source intact.
2. Open the Color Library panel and choose **Recolor > Use active product**. The bound source name remains visible. This creates working copies; it does not edit the original source.
3. In the product preview, make/refine the garment selection using normal Photoshop tools. Choose **Use material selection**, or select a reviewed existing mask/channel/path in the mask selector. Nondefault mask modifiers/combined masks require a designer-created selection in this version.
4. Choose **Choose approved color** in Target color (or **Browse library** in the header), select the client and approved color, then choose **Apply Color** on the intended Crop/Full reference. This opens a fresh temporary copy of that approved file and returns to the recoloring controls. Ordinary **Open Reference** remains available separately.
5. On that reference, select representative diffuse fabric, excluding background, bright highlights and deep shadows. Choose **Sample reference**. The preview document becomes active again. Initial preparation is deliberately designer-assisted; automatic material/reference-region analysis is not implemented.
6. Choose **Preview color**. The first preview fits and compares three adjustment-only native methods, then refines the best rendered candidate. After it finishes, use **Try a recoloring method** and **Refresh preview** to try a specific method. Its review identifies the actual rendered method and reports color difference, shadow/highlight differences, tonal clipping and relative detail when measurable. Use **Show original** and inspect the canvas at 100%. Choose **Manual adjustments** to adjust intensity, brightness, contrast, shadows and highlights. Refreshing refits the chosen method and replaces manual settings. Cancel stops fitting after the current native operation and restores the last completed preview when available.
7. Choose **Apply Color** to keep the editable result. Use **Save PSD/PSB** for the editable master or **Save JPEG** for the delivery image. Each button has its own filename/folder picker and creates only its selected format. Either can be used first; JPEG export does not require a saved master. Final touch-ups and the material mask remain editable. Existing files are refused. PNG/WebP and client-specific delivery presets remain pending.
8. For another target, browse the library and choose its reference. Each variant uses the same frozen original, not the previously recolored result. The target selector retains sampled targets and their individual controls for this session. Use **New variant** after manual edits or to replace the shared mask. **Change product** allows a different product without discarding open results.

The source/reference must have an explicit profile interpretation. Tagged inputs are read with their actual profiles and converted on working copies. Missing HEX values do not matter. The pilot does not infer a profile for an untagged image.

Disabled controls express prerequisites: **Preview color** needs a captured material mask and sampled approved reference; **Apply Color** needs a completed preview; both save buttons need an applied result. Status and errors stay visible above the scrollable controls. Selecting a different method takes effect when the designer chooses **Refresh preview**.

## Designer-reviewed method selection (0.6.12)

The [designer feedback record](DESIGNER_METHOD_FEEDBACK.md) captures the preferred Navy → Arctic Aqua Tint and levels preview and the reported White Gardenia exceptions. Automatic now prefers Tint and levels for measured dark-to-light transitions (source L* ≤50, target L* ≥60, rise ≥20), while retaining the rendered comparison and explicit manual overrides. Its preferred method gets continued refinement rather than losing to a lower color-difference score from a visually inferior method.

Near-white targets receive a conservative D starting seed and additional bright-region fabric-detail measurements. A method that clips tones, washes out bright fabric or flattens fold depth loses preference. Gradient and tone is the preferred near-white fallback only when it retains enough depth; Hue and selective color stays available for manual comparison. The preview review records the policy and explains any fallback. These are transparent designer-feedback rules, not a neural-model training run or client-library approval.

Version 0.6.12 changes candidate initialization and ranking; saved recipe descriptors remain replay-compatible. The active designer review is not reloaded or replaced during inspection. Finish/save it before reloading the new build.

## Slider stability and natural lighting (0.6.11)

A reported shutdown on 27 October was confirmed as a Photoshop 25.3.1 native access violation while a manual slider was being dragged. It was not reproduced by the controlled 1300 × 2000 modeless stress probe, so the native crash cause remains unconfirmed. The probe reproduced the repeated native selection notifications; those warnings also occurred without a crash and are not proof of the cause.

Manual changes now wait for a 180 ms pause before rendering the latest settings. The controller avoids repeatedly rebuilding the native target selector and repainting the entire panel during a drag. In the controlled probe, each 120-event drag dropped from 30–35 native renders to one, with no concurrent Photoshop transactions. Apply remains unavailable until the final update completes. A bounded, workstation-only `recolor-pilot-actions.json` journal records recent methods, parameters and completion status in the plugin data folder; it contains no images or source/reference paths, and logging failures cannot block recoloring.

Large dark-to-light previews use version-4 lighting curves: local exposure-like scaling around the material midpoint plus a smooth highlight shoulder, rather than a bright midpoint followed by a flat upper ramp. Candidate scoring now measures source-relative fold contrast and spatial lighting error in addition to normalized fine detail. This closes a blind spot where a flattened result could still earn a good texture score. Version-1/2/3 recipes replay through their original descriptors. New light-to-dark previews retain version 3.

The [stability and lighting verification](verification/product-pilot-stability-lighting-2026-10-27.json) records 31 native fixtures, six UXP interactions and comparative patches on the saved Navy source using approved Cloud and Arctic Aqua references. The previous patch renders retained approximately 0.20–0.25× source-relative fold contrast; the new renders retained approximately 0.95–1.00×. Cloud's diffuse color difference was about 0.78; Arctic Aqua's was about 3.54 in this bounded comparison. Better lighting does not imply final color approval. The diagnostic rectangles are not full garment masks or delivery images. The original Navy document and its history were preserved.

## Preview and adjustment workflow (0.6.10)

The source and target diffuse L* measurements classify the change as similar lightness, darker to lighter, or lighter to darker. An absolute difference of 20 L* or more receives an extended search: up to 96 renders for Automatic and 64 for an explicit method, with broader initial brightness and gamma steps. Other transitions use up to 64 and 40 renders respectively. These thresholds guide search effort; the winning method is always selected from actual rendered color, tone, clipping and detail scores. They do not certify human-edit quality or reconstruct missing source texture.

Those demanding transitions also use version-3 source-anchored tone curves. The measured source midpoint becomes an explicit curve knot mapped to the required output tone, with monotonic shadow/highlight ramps shaped by the training families. Gradient and tone first normalizes the source midpoint to 128 because the Gradient Map supplies the target lightness itself. This avoids dark-to-light undercorrection from blending a fixed population curve with only a weak source anchor. Version-1/2 recipes retain their previous descriptors and replay behavior.

Method selection stays separate from the completed preview. Selecting another method disables Apply and manual controls until Refresh finishes, or the user selects the currently previewed option again. Each refreshed option retains its own measured review for this target. Manual sliders update the current preview through a serialized, coalescing queue; Apply remains disabled until the latest slider request settles. Manual review measurements are recomputed, while the original fitted-method comparison remains separately recorded. Apply commits that exact displayed recipe and records whether it was automatic, explicitly chosen, or manually adjusted.

Search trials cannot become a completed first preview. Cancellation or failure restores the previous completed recipe and Before/After visibility when possible; if restoration fails, Apply remains unavailable. A new variant runs a fresh automatic comparison rather than silently reusing a previous explicit method. The manual disclosure uses an explicit button and hidden container for Photoshop UXP compatibility.

The [0.6.10 verification record](verification/product-pilot-preview-adjust-2026-10-27.json) covers application tests, 31 native Photoshop fixtures and six UXP UI interaction checks. On the synthetic extreme-transition fixtures, the new tone mapping reduced dark-to-light diffuse Delta E from about 8.99 to effectively zero; light-to-dark measured about 0.01. Relative detail remained approximately 1.00, without added clipping or changes outside the material mask. These are controlled synthetic tests, not a production-garment or human-edit quality certification. `npm run test:recolor:adjustments` runs the scoped native UI checks against an already loaded panel, using an in-memory image adapter without touching Photoshop documents.

## TIFF-calibrated human-edit matching (0.6.9)

The 0.6.9 pilot adds population-level standards learned from 32 unique approved human recipes in 34 layered TIFF files. It never selects settings by color name. Approved-reference sampling now records shadow, diffuse and highlight Lab zones. When those richer measurements are available, all candidates use interpolated dark/mid/light multipoint Curves; candidate D follows the dominant human sequence with source neutralization, tinted Black & White, editable Color Balance and separate lighting controls. Automatic fitting evaluates lightness, contrast, shadows, highlights, chroma, gamma and undertone balance with a 64-render budget.

The score now includes diffuse Delta E, shadow/highlight distribution, zonal color, clipping and source-detail preservation. Older saved or diffuse-only targets retain their previous engine and rendering behavior. Texture pixels appeared in only 3 of 32 unique recipes, so the pilot preserves and measures source texture but does not synthesize raster texture automatically. See [the TIFF audit](TIFF_HUMAN_TRAINING_AUDIT.md) and [machine-readable standards](verification/tiff-human-training-standards.json).

## Recoloring without a Solid Color fill

**Automatic — best match** compares **Hue and selective color** (B), **Gradient and tone** (C), and **Tint and levels** (D). These use native Hue/Saturation, Selective Color, Gradient Map, tinted Black & White, Levels, and Curves adjustment layers. They retain the shared editable material mask, original source structure, and independent variants. Existing layers in the source or completed masters are preserved. Method A remains supported internally for historical recipes and controlled comparisons; the product workflow does not render or offer it.

Fitting gives each eligible method a bounded coordinate-search pass, including hue/saturation refinement for B, before selecting and refining the strongest measured result. Current evaluation budgets depend on the measured lightness change as described above. The final evaluation restores and verifies the winning rendering. Integrity failures are excluded, clipping/detail penalties remain active, and cancellation is checked between evaluations. A completed fitting pass records its per-method measurements; subsequent manual parameter changes produce fresh current-preview measurements while retaining the original comparison as fitting history.

The [adjustment-only verification record](verification/product-pilot-adjustment-only-2026-10-19.json) records application regressions, native Photoshop fixtures, and the loaded-panel workflow. On the synthetic Wine fixture, the previous 18-evaluation Auto selected D with diffuse-anchor ΔE00 1.67; the new 40-evaluation comparison selected B at 0.64, with no protected-pixel changes or added tonal clipping and a normalized detail ratio of approximately 1.001. Both selected methods already avoid a Solid Color fill: the improvement demonstrates the stronger fitting search on this fixture, not that removing a fill layer alone improves quality. The different evaluation budgets are intentional and can increase matching time. This is not a production-garment or human-edit quality claim.

## Reference identity and failure behavior

The library still owns approval status. Targets retain client/color/reference/version identity, original filename, declared checksum and historical approval metadata. A fresh temporary file is hashed before opening. A declared checksum mismatch rejects it. After opening, the reference's full rendered-pixel fingerprint is checked at sampling: changing a selection is allowed; editing image pixels is refused. Pixel fingerprints establish session consistency, not another client approval or physical-swatch accuracy.

Fitting/applying rechecks that the selected version is still present in the current client catalog. Withdrawal/version/client changes block subsequent operations while preserving completed variants. As with the existing library, offline cached catalogs cannot establish a withdrawal that has not been synchronized yet.

Saving protects source/reference paths and refuses existing nonempty output files. A versioned local session record includes recipe, source interpretation, approved reference identity, export metadata and quality diagnostics. If record storage fails after saving, the error reports the completed artifact paths; the files are retained. These records do not implement full job recovery or automatic reopening/rebinding of editable results.
